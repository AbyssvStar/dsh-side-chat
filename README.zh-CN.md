# dsh-side-chat

**中文** | [English](README.md)

为 DSH 网页界面提供一个类似 Codex 的侧边对话：从主线任意一轮已完成的对话分叉出去，在右侧栏继续，聊完把结论带回主线；主线不被打断。

侧聊是一个真正的分叉会话：它复制主线到分叉点为止的完整事件前缀，之后以自己的模型与工具独立运行。两侧默认互不流动，不必担心污染主线。

## 特性

### 分叉与会话

- **从任意一轮分叉。** 主线每一轮已完成的回答下方都有 `◫` 动作，在该轮分叉，并把子会话开在右侧栏。与内置的「分支」不同，它不会把当前主线切走。
- **完整的对话面板。** 面板复用主窗口的对话视图，拥有独立的输入框、工具调用与审批，不是只读预览。
- **运行状态可见。** 侧聊在后台继续跑时，它的标签标题会带一个脉冲指示，不必切过去确认。

### 带回主线

- **先总结，再带回。** 在侧聊里点 `↩`，先由侧聊把这次对话归纳成一段结论（这次归纳会作为一轮对话出现在侧聊里，过程可见），再把结论放进主线的输入框。是否发送由你决定。
- **只带回选中的部分。** 先选中文字再点 `↩`，带回的只有选中片段，跳过归纳。
- **不代替你发言。** 带回只写草稿。输入框暂时接不了草稿时（会话已切走、页面刚重载）会直接报错，不会退化成替你发一条消息。

### 入口

- **分栏入口。** 右侧栏为空时，入口列表（终端、文件预览所在的位置）提供两张卡片：
  - **侧聊 · 接着主线**：从主线最新一轮已完成对话分叉；
  - **侧聊 · 空白**：新建一个不携带任何上下文的会话，用于与当前任务无关的问题。空白侧聊没有来源，因此不提供带回按钮。
- **在侧聊中提问。** 在页面任意位置选中文字（主线回答、工具输出均可），旁边出现 `↬` 按钮；点击后把该片段写入当前侧聊的输入框，没有打开的侧聊时则先新建一个。

### 生命周期

- **自动命名。** 分叉会原样继承父会话标题，因此侧聊打开后会被重命名为 `侧聊 · MM-DD HH:mm`，便于在会话列表中区分。
- **关闭时询问归档。** 关闭侧聊标签后，页面顶部会浮出一张卡片询问是否归档。归档后该会话从列表中移除（仍可在归档过滤中找回）；选择保留则不作改动。

## 安装

`dsh plugin` 把参数原样转发给 pnpm，因此 GitHub 仓库、Git 地址、tarball 与本地目录都可以作为来源。仓库中已包含构建好的 `lib/`，从源码安装无需构建。

### 从 GitHub 安装

```sh
dsh plugin --profile web add github:AbyssvStar/dsh-side-chat
```

默认取 `main` 分支的最新提交；需要固定版本时在末尾加 `#<标签或提交>`：

```sh
dsh plugin --profile web add github:AbyssvStar/dsh-side-chat#<标签或提交>
```

### 从 npm 安装

```sh
dsh plugin --profile web add @abyssvstar/dsh-side-chat
```

## 使用

| 位置 | 动作 | 结果 |
| --- | --- | --- |
| 主线某一轮下方 | `◫` | 在该轮分叉，右侧栏打开侧聊 |
| 右侧栏空状态 | 「侧聊 · 接着主线」 | 从最新一轮分叉并打开 |
| 右侧栏空状态 | 「侧聊 · 空白」 | 新建不带上文的侧聊并打开 |
| 侧聊内 | `↩` | 侧聊归纳本轮结论，写入主线输入框 |
| 页面任意选区 | `↬` | 把选中片段写入侧聊输入框 |
| 侧聊标签页关闭后 | 浮层「归档 / 留着」 | 归档该会话或保持原样 |

## 工作原理

**会话。** 侧聊由 `sessions.fork` 创建，宿主持久化一份到分叉点为止的前缀副本，并在日志头记录 `parentSession`。两侧此后各自追加事件，互不写入。

**读取结论。** 由于仓库外插件无法向会话日志写入模型可见的自定义事件（持久化层会拒绝未知事件类型，`ignorable` 后门仅限内置插件且不进入模型可见面），浏览器部分改由宿主提供的只读路由读取：

```
GET /side-chat/handoff?child=<sessionId>&parent=<parentSessionId>
```

宿主通过 `sessionPersistence` 只读地扫描子会话日志，取最后一条含正文的助手消息。带回分为两步：先读取当前答案作为基线，再触发侧聊归纳，然后轮询该路由，直到出现与基线不同的新答案且该轮已结束（两分钟超时后退回基线答案）。

**写入草稿。** 结论通过 `requestDraftInitialization` 写入主线输入框。该调用不可用时报错并提示，不做降级。

**空白侧聊** 走 `sessions.create`，不产生 `parentSession`，因此地址中省略 `parent`，带回动作自然不出现。

## 访问控制

两条路由实际只监听本机，但监听本机不是权限检查：浏览器加载的任何页面都可以尝试请求。因此有两道低成本限制：

- **来源。** `Sec-Fetch-Site` 不是 `same-origin` 或 `none`，或 `Origin` 不是本机的请求一律返回 `403`。
- **归属。** 读取路由要求同时提供 `child` 与 `parent`，且日志头中的 `parentSession` 必须匹配，否则返回 `403`。知道会话 id 不等于有权读取其内容。

此外，写路由要求 `X-Side-Chat: 1` 请求头：跨站表单与图片无法设置自定义头，跨站 `fetch` 设置该头需要先通过预检，而本服务不放行预检。

这些措施不是身份认证（该连接上唯一的凭据是网页自身的登录态），也不能阻止本机的恶意进程；它们拦截的是恶意网页。

## 已知限制

- **分叉会话必定出现在会话列表中。** DSH 没有隐藏会话的开关，且现有替代方案代价更高：归档会使会话无法再运行回合，改为 `origin: 'subagent'` 会把输入框变成只读。因此插件只做两件事：打开时赋予可区分的名称，关闭时询问是否归档。
- **归档后无法继续对话。** 这是 DSH 的设计，归档会话在第一步即被拒绝。归档只应用于确定不再需要的侧聊。
- **归纳是一次真实的模型调用。** 带回会多花一次调用、多出一条消息，期间侧聊显示为运行中；两分钟内未完成则退回当前答案。
- **宿主路由可选。** 没有 webserver 的环境（headless、tui）中面板仍可用，带回退化为复制粘贴。
- **父子关系按浏览器保存。** 关联记录在 `localStorage` 的 `dsh.side-chat.v1` 下；清除存储或更换浏览器后，仍可通过会话列表中的 `parentSessionId` 识别分叉，带回功能不受影响。
- **选区按钮是文档级元素。** 文本选区属于浏览器而非某个会话，因此它不挂在会话作用域的座位上；选区位于自身面板内时会自动隐藏。

## 兼容性

插件依赖若干尚未视为公开 API 的接缝：`ctx.get('agents')`、`ctx.get('sessionPersistence')`、`ctx.get('webServer')`，以及客户端座位 `conversation.chat.turnTail`、`sidebar.right.pane.tab` 及其 `.title`、`sidebar.right.tab.guide.entry` 与 `requestDraftInitialization`。DSH 升级可能移动其中任意一个。

```sh
npm run check    # 等价于 node scripts/check-dsh-compat.mjs <dsh 根目录>
```

该脚本检查每个接缝在已安装的 DSH 中是否存在，并指出失效的那一个。当前按 DSH 0.2.1-rc.2 编写。
