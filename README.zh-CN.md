# dsh-side-chat

给 DSH 网页版加一个 Codex 那样的「侧边对话」：从任意一轮已完成的对话分叉出去，在右侧栏
继续聊，聊完再把结论带回主线。主线不受打扰，侧聊也不会跑掉。

侧聊不是草稿纸，而是一个真正的分叉会话：它复制了主线到分叉点为止的完整前缀，然后用自己
的模型和工具独立往下走。两边默认互不流动，所以侧聊可以放心地去试一个坏主意。

## 怎么用

- **从任意一轮分叉。** 主对话里每一轮已完成的消息下方都有一个 `◫` 按钮。点它就在这一轮
  分叉，子会话直接开在右侧栏。和内置的「分支」不同，它不会把你当前的主线切走。
- **右侧栏里是一个完整的对话。** 侧聊复用了主窗口同一个对话视图，有独立的输入框、工具
  调用和审批，不是只读预览。
- **带回主线。** 在侧聊里点 `↩`，它最后一段回答会被放进主线的输入框，先给你过目、可改、
  你自己决定什么时候发。如果主线的输入框暂时接不了草稿（会话切走了、页面刚重载），就把
  这段文字作为一条消息发过去——那是模型唯一能看见的另一条通道。
- **作为背景带回。** `Shift` + 点 `↩`，同一段文字改成写进主线的上下文：下一轮模型能看见
  它，但不会替你说话，也不会唤醒空闲会话。
- **只带回你选中的那段。** 先选中文字再点 `↩`，带回的就只有选中部分，而不是整段回答。
- **反向送一段过去。** 在页面任何地方选中文字（主线的回答、工具输出都行），旁边会浮出一个
  `↬` 按钮。点一下就把这段放进当前侧聊的输入框；没有侧聊时就新开一个，让侧聊看着你正在
  看的东西回答。
- **从分栏直接开一个。** 右侧栏空着时的那一列入口卡片里（终端、文件预览都在那儿）多了一
  个「侧聊」：点它就从主线最新一轮分叉开一个侧聊，不用先去找某一轮的按钮。
- **侧聊有名字了。** 每开一个侧聊，会自动把它命名为「侧聊 · 月-日 时:分」，所以会话列表
  里一眼能看出是哪一条，而不是一排和主线一模一样的标题。
- **关闭即归档。** 关掉侧聊的标签页时会问一句要不要归档：归档后它从会话列表里消失（仍可
  在归档过滤里找回），不归档就原地留着。

## 安装

```sh
dsh plugin --profile web add link:/absolute/path/to/dsh-side-chat
```

然后刷新网页。用 `link:` 时 `lib/` 下的文件是从这份检出里读的，改完刷新就生效；host 那半
（`lib/index.js`）由 Node 进程加载，要重启 `dsh web`。

## 带回是怎么实现的

DSH 不允许仓库外的插件往会话日志里追加模型可见的自定义事件：持久化层读到已知集合之外的
事件类型会整份拒绝，而 `ignorable` 那条后门只给内置插件用、且永远到不了模型面前。所以：

- **读**：浏览器半部用 `GET /side-chat/handoff?child=<会话 id>&parent=<父会话 id>` 问
  host 半部要侧聊最后一段回答；host 半部通过 `sessionPersistence` 只读地翻日志，不新增
  依赖。
- **写**：带回时优先落到主线的草稿（`requestDraftInitialization`），落不下去才退化成发
  一条 `user/message`；`Shift` 带回则走 `POST /side-chat/context`，由 host 侧
  `agent.inject()` 写成一条 `source.kind` 为 `side-chat` 的用户消息。这些都是已知事件
  类型，日志仍然可读，也不会冒充你说的话。

## 谁能调这两个路由

两条路由实际只监听本机，但「本机」不是权限检查——浏览器打开的任何页面都能试。所以加了两
道便宜的栅栏：

- **来源**：`Sec-Fetch-Site` 不是 `same-origin` 或 `none`、或者 `Origin` 不是本机的请求
  一律 `403`。
- **归属**：带回路由同时要 `child` 和 `parent`，日志头里的 `parentSession` 对不上就
  `403`。知道一个会话 id 不等于有资格读它的正文。

写路由另外要求一个 `X-Side-Chat: 1` 头：跨站表单和图片设不了自定义头，跨站 `fetch` 想设
就得先过预检，而这个服务不放行预检。

这些都不是身份认证（这条 socket 上唯一的凭据是网页自己的登录态），也拦不住本机上的恶意
进程；它们拦的是恶意网页。

## 已知限制

- **分叉本身一定会出现在会话列表里。** DSH 没有「隐藏会话」这个开关，而所有受支持的替代
  方案都更糟：归档会让会话再也跑不了回合，改成 `origin: 'subagent'` 会把输入框变成只读。
  所以插件能做的是两件事：开的时候给个能分辨的名字，关的时候问一句要不要归档。
- **归档之后不能再聊。** 这是 DSH 的设计（归档会话在第一步就被拒），所以归档只适合你真
  的不想再要这个侧聊的时候。
- 只有浏览器那半必须依赖 GUI；host 路由是可选的。没有 webserver（headless、tui）时面板
  照样能用，带回退化成复制粘贴。
- 侧聊的父子关系记录在浏览器 `localStorage` 的 `dsh.side-chat.v1` 下；换浏览器或清掉存
  储后，仍能靠会话列表里的 `parentSessionId` 判断出这是分叉，带回按钮照常出现。
- 选区浮层是一个文档级元素而不是某个座位：选中文字是浏览器的事实，不是某个会话的事实。
  选在自己面板里时它会自己躲开。

## 测试

```sh
npm test
```

两个套件都不需要浏览器：`test/client.test.mjs` 用桩运行时跑真的 `lib/client.js`，
`test/host.test.mjs` 驱动两条路由和日志扫描。

## 兼容性

插件依赖了一些还没被当成公开 API 的接缝：`ctx.get('agents')`、
`ctx.get('sessionPersistence')`、`ctx.get('webServer')`，以及四个客户端座位
（`conversation.chat.turnTail`、`sidebar.right.pane.tab` 及其 `.title`、
`sidebar.right.tab.guide.entry`）和 `requestDraftInitialization`。DSH 升级后这些都可能
挪位置。

```sh
npm run check            # 或 node scripts/check-dsh-compat.mjs <dsh 根目录>
```

这个脚本会检查每个接缝在已安装的 DSH 里是否还在，并指名挪走的那一个。

设计取舍与实现修订记在 [`docs/design.md`](docs/design.md)。
